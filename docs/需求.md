# RetailGuard Copilot 升级需求

> 文档定位：**业务侧诉求 + 用户场景 + 验收线**。技术方案见 `设计.md`，落地节奏见 `升级计划.md`。
> 风格：轻量叙事 + 关键节用表格。所有数字与目标值在 W2 评测基线跑出后回填。

---

## 1. 背景与目标

现有项目 RetailGuard Copilot 是一个电商售后多智能体客服系统，技术骨架（LangGraph + FastAPI + Vue3 + MCP scaffold）已搭好，但 README 自称的功能大多是 demo 级别——没有 RAG、没有评测、没有可观测、灰度三版本无功能差异、风控是写死的、Agent 之间只是路由不是协作。

**升级目标**：把项目从「功能 demo」升级到「可作为简历主项目投递的工程作品」，覆盖 2026 AI Agent JD 的全部硬关键词，业务侧能讲故事、技术侧能深聊架构。

**周期**：9 周全职。

**成功标准（顶层）**：
- 12 条端到端验收场景全部跑通（详见第 7 节）
- 评测报告显示 v3 相较 v1 核心指标显著提升
- 完整栈 `docker-compose up` 一键拉起、5 分钟可演示
- CI 全绿、测试覆盖 70%+
- 配套博客与简历段落定稿

## 2. 用户与场景

四个角色，每个角色一句话定义 + 一条主路径。

### 2.1 顾客（终端用户）

通过聊天界面咨询售后、查订单、申请退款、改地址。**最在意**「问得清楚、办得快、有理有据」。

> 主路径：登录 → 用 ChatView 提问「我上周买的蓝牙耳机能退吗」→ 系统检索退换货政策 → 给出带引用的答案 + 一键发起退款 → 看到工单进度。

### 2.2 客服坐席

承接需要人工介入的会话、查会话历史、跟进工单。**最在意**「能看到上下文、能快速结案」。

> 主路径：登录 → 看 DashboardView 待处理工单列表 → 进入某个会话查看 Agent 决策链 → 必要时接管对话或追加备注 → 结案。

### 2.3 风控人员

审核被系统打高风险分的退款、查看决策依据、决定通过/拒绝。**最在意**「为什么被判高风险、能不能解释清楚」。

> 主路径：登录 → 看 ReviewView 人审队列 → 点开某条 → 看三层风控决策链可视化（规则层命中哪些 / 特征层异常分 / LLM 判定与理由）→ 通过或驳回 → 工作流自动 resume。

### 2.4 管理员

调灰度权重、配租户、看多维度指标、看成本面板。**最在意**「数据看得见、版本切得动、成本可控」。

> 主路径：登录 → AdminView 看 v1/v2/v3 实时指标对比 → 调整流量权重 → 看 token 成本曲线 → 必要时新建/禁用租户。

## 3. 范围边界

### 做

- 四角色完整闭环（顾客 / 客服 / 风控 / 管理员）
- JWT 登录 + RBAC（按钮级 + 接口级）
- 多租户（共享库 + tenant_id 逻辑隔离，5 个 mock 租户）
- RAG 知识问答（带引用）
- Multi-Agent 协作（Planner + Critic + Interrupt 人审）
- 三层融合风控引擎（规则 + 特征 + LLM，可解释决策链）
- 动态模型路由 + 语义缓存
- 灰度三版本真功能差异化 + A/B 对比
- Celery 异步任务
- 全链路 Langfuse trace + 5 维评测体系
- MCP 真 stdio 协议对外暴露
- 中规模 mock 数据（1000 KB / 1万订单 / 1000 用户 / 5 租户）+ 压测脚本

### 不做

- 移动端 H5、小程序、App
- 接真实电商系统（订单 / 物流 / 支付）
- 接真实支付与退款渠道
- 接真实 IM 与短信通道
- 国际化 i18n（仅中文）
- 数据库行级隔离（共享库逻辑隔离已够展示）
- 算法层面的微调（SFT/LoRA），仅做应用层

## 7. 验收主线（12 条端到端场景）

1. **知识问答**：顾客问"耳机能 7 天无理由吗" → RAG 检索 → 流式带引用答案
2. **简单业务**：顾客"查订单 12345" → 跨租户访问被拒
3. **复杂业务**：顾客"退两件其中一件换地址再发" → Planner 拆 3 步 → Critic 校验 → 完成
4. **风控触发**：顾客退 999 元 → 三层融合打分 → 风控员看决策链 → Approve → resume
5. **模型路由**：简单 query 走便宜模型（trace 验证）
6. **语义缓存**：相似 query 二次访问命中（trace 显示 cache hit）
7. **异步任务**：客服触发批量退款审核 → Celery 后台跑 → 前端进度条 → 完成通知
8. **灰度对比**：管理员把 v3 权重调到 0 → 流量切 v2 → dashboard 实时反映
9. **多租户隔离**：A 租户管理员登录看不到 B 租户任何数据
10. **观测**：所有 case 在 Langfuse 看到完整 trace + 成本
11. **评测**：`make eval` 产出 markdown 报告（含三版本对比）
12. **MCP 对外**：Claude Desktop 通过 MCP 调本系统 query_order 工具返回数据

## 8. 风险与缓解

| 风险 | 等级 | 缓解 |
|---|---|---|
| W4 三层风控联调复杂 | 高 | 分小步骤（rules→features→llm→fusion），每层独立测 |
| RolloutManager 当前未接入 | 高 | W5 第一天先把 supervisor 路由接上再差异化 |
| MCP 协议层需整体重写 | 中 | 保留现有 25 个工具注册作 registry，外层用 mcp SDK 包 stdio |
| 评测数据集合成质量 | 中 | 关键样本人工校 20%、宁可少而精（150 条也行） |
| Planner 输出不稳定 | 中 | Pydantic schema + 强约束 prompt + 重试 |
| 9 周节奏溢出 | 中 | 每周一晚盘上周遗留，宁可砍 W8 内容也要保 W1-W7 质量 |
| 多租户改造侵入面广 | 中 | W1 起 tenant_id 贯穿数据模型，避免后期回头改 |
